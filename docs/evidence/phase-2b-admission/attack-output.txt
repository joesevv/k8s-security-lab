Phase 2b — admission control attack demo (captured 2026-07-25)
Cluster: kind seclab (context kind-seclab), Kubernetes v1.35.5 (client v1.36.1).
Kyverno: chart kyverno/kyverno 3.8.2, app v1.18.2, namespace kyverno.
Controls under test: 4x policies.kyverno.io/v1 ValidatingPolicy in policies/,
plus 1 ImageValidatingPolicy in policies/supply-chain/, all with
validationActions [Deny]; and the in-tree Pod Security Admission "restricted"
profile enforced on the demo namespace.

Threat blocked: "a workload that grants itself node-level power at deploy
time." Privileged containers, mutable :latest tags, un-dropped or added-back
Linux capabilities, images from unvetted registries, and hostPath mounts of the
node root are all container-escape or supply-chain footholds. Admission control
rejects them BEFORE the object is persisted, so there is no running pod to
detect, evict or forensicate afterwards.

TWO-NAMESPACE DESIGN — read this before the outputs below.
Pod Security Admission is an in-process API-server plugin and runs BEFORE
admission webhooks; when PSA enforce rejects a pod it short-circuits and the
webhook is never called. The demo namespace carries
pod-security.kubernetes.io/enforce=restricted, so most of these attack pods
would be stopped by PSA there and the Kyverno denial would never be observable.
Namespace demo-kyverno-only therefore carries pod-security.kubernetes.io/warn
ONLY, with no enforce: the same pods reach the webhook, PSA still prints its
advisory warning, and the Kyverno denial is the thing that actually fails the
request. So:
  demo               -> demonstrates the PSA layer (ATTACK I)
  demo-kyverno-only  -> demonstrates the Kyverno layer (ATTACKS A-H)
All five policies select both namespaces.

MATCH SCOPE — the policies reach pod controllers through EXPLICIT resourceRules
(apps/v1 deployments, statefulsets, daemonsets, replicasets; batch/v1 jobs,
cronjobs) alongside the pods and pods/ephemeralcontainers resources, plus a
podSpec CEL variable that resolves the three pod-spec shapes. This is NOT
Kyverno autogen: spec.autogen.podControllers is a NO-OP on Kyverno 1.18.2 and
was removed rather than left in place implying coverage it did not provide (see
commit d9d04d0). ATTACKS F, G and H are the tests that the explicit rules work.

division of labour: NO ValidatingPolicy in policies/ covers hostPath, hostPID,

enforce=restricted on the demo namespace is the control that closes it. The
