Phase 2b — Kyverno admission control attack demo (captured 2026-07-21)
Cluster: kind seclab (context kind-seclab), Kubernetes v1.35.5
Kyverno: chart kyverno/kyverno 3.8.2, app v1.18.2
Policies: 4x policies.kyverno.io/v1 ValidatingPolicy, validationActions [Deny],
scoped to the demo namespace. Each attack manifest violates exactly ONE policy
and complies with the other three, so each denial cleanly cites its target
policy.

Note: the demo namespace also carries Pod Security Admission warn labels, so
two attempts additionally print a non-blocking "Warning: would violate
PodSecurity" line. The BLOCK in every case is the Kyverno admission webhook
denial ("Error from server: ... vpol.validate.kyverno.svc-fail denied the
request"), which is why the pod is never created.
